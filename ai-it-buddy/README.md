# AI IT-Buddy

Помощник стажера в первые недели: доступы, техподдержка, оборудование, путь адаптации.
Hack&Change 2026, кейс Авито. Данные синтетические, инструкции в `data/kb` тестовые и не являются регламентами Авито.

## Архитектура

```
UI ──► core (Go) ──► agent (Python, LangGraph) ──► llm-gateway (Go) ──► LLM
         ▲  │                │
         │  └─ заявки, права │ MCP + JWT пользователя
         └───────────────────┘
       Prometheus ◄── /metrics (core, llm-gateway) ──► Grafana
```

- `core` - HTTP API для интерфейса и четыре MCP-сервера: `/mcp/access`, `/mcp/helpdesk`, `/mcp/inventory`, `/mcp/onboarding`.
  Права, заявки, статусы и согласования живут здесь.
- `agent` - LangGraph: модель выбирает инструмент, ядро его выполняет. Сам агент ничего не меняет.
- `llm-gateway` - агент просит роль (`main`, `small`, `validator`), шлюз выбирает модель и переключается на запасную.

Права проверяет сервер. Пользователь в MCP берется из JWT, а не из аргументов модели.
Агент получает токен с аудиторией `mcp` на 5 минут: им можно создать черновик, но нельзя подтвердить заявку.
Подтверждает человек в интерфейсе токеном сессии (`ui`). Запросы не по роли не блокируются: стажер видит причины,
а заявка сначала уходит наставнику.

## LLM

По умолчанию OpenRouter, бесплатные модели:

- `main`, `small`: `nvidia/nemotron-3.5-super-vl:free`
- `validator` и запасная: `thinkingmachines/inkling-small:free`

Ключ: https://openrouter.ai/settings/keys, переменная `OPENROUTER_API_KEY` в `.env`. Лимит: 50 запросов в день на аккаунт.

Другой провайдер (любой OpenAI-совместимый): правится `deploy/llm-gateway.yaml`, блоки `upstreams` и `targets`.
DeepSeek уже настроен: в `.env` строки `LLM_CONFIG=llm-gateway.deepseek.yaml` и `DEEPSEEK_API_KEY=...`.

## Запуск

Docker, папки `ai-it-buddy` и `llm-gateway` рядом.

```bash
cp .env.example .env          # вписать OPENROUTER_API_KEY
docker compose up -d --build
curl 127.0.0.1:8080/healthz
python3 scripts/check_llm.py  # 3 запроса к LLM
python3 scripts/demo.py       # 5 сценариев, около 10 запросов
```

| | |
|---|---|
| API | http://127.0.0.1:8080/api, спецификация: `/api/openapi.yaml` |
| Grafana | http://127.0.0.1:3001, дашборд AgentOps открывается на главной |
| Prometheus | http://127.0.0.1:9091 |
| LLM-шлюз | http://127.0.0.1:4001 |

## Сценарии

1. Доступ по описанию задачи. «Нужно поправить алерт» -> Grafana, проект своей команды, уровень write -> черновик ->
   подтверждение -> согласует владелец проекта -> шаг адаптации «доступ к Grafana» закрывается сам.
2. Не по роли. Стажер просит прод -> причины и совет обсудить с наставником -> очередь наставника -> отказ с причиной.
3. Инцидент. VPN лежит -> «проблема не у тебя», тикет не создается: сервер не дает завести дубликат.
4. Оборудование. Позиции нет -> альтернативы из наличия, лист ожидания, закупка только в пределах нормы роли.
5. Путь адаптации. Шаги по неделям, у каждого свой способ подтверждения: сам, наставник, руководитель, система.

Инцидент для демо:

```bash
curl -X POST 127.0.0.1:8080/api/demo/incidents -H 'X-Demo-Token: demo' \
  -d '{"service":"vpn","title":"Недоступен шлюз VPN","active":true}'
```

## Метрики

Дашборд AgentOps в Grafana:

- доля вопросов, закрытых без наставника;
- конверсия черновик -> подтверждение;
- сколько раз помощник не дал завести тикет во время инцидента;
- попытки выйти за права;
- доля заявок не по роли;
- токены на ход диалога;
- переключения на запасную модель;
- p95 ответа.

Счетчики ядра начинаются с `buddy_`, шлюза - с `llm_gateway_`.

## Где что

- `core/internal/domain` - заявки, политика, склад, база знаний, адаптация
- `core/internal/mcpapi` - инструменты для агента
- `core/internal/httpapi` - API для интерфейса, `openapi.yaml`
- `core/internal/authn` - имитация IdP (JWT)
- `agent/buddy_agent` - граф, промпт, HTTP-вход агента
- `data/seed` - сотрудники, каталог сервисов, роли, склад, шаги адаптации
- `data/kb` - база знаний
- `deploy` - конфиги шлюза, Prometheus, Grafana
- `docs/api.md` - API для фронтенда

## Ограничения прототипа

- Состояние хранится в памяти ядра и сбрасывается при перезапуске.
- Здоровье сервисов задается через `/api/demo/incidents`, а не берется из мониторинга.
- История диалогов хранится в памяти агента. Поэтому агент запускается одним процессом.
