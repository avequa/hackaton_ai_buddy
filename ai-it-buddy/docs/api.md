# API для фронтенда

- `contracts/api.ts` - готовые Zod-схемы, типы и клиент на fetch. Положи в проект и вызывай `createApi(...)`:
  ответы проверяются схемой, ошибки приходят как `ApiError` со статусом и текстом. Нужен `zod` 3.x или 4.x.
- `core/internal/httpapi/openapi.yaml` - полная схема, отдается на `GET /api/openapi.yaml`.

Ниже - то, что не видно из схемы.

## Подключение

Ядро: `http://127.0.0.1:8080`. Для dev-сервера на `localhost:5173` CORS уже разрешен
(`CORS_ALLOWED_ORIGINS` в compose). Проще всего проксировать `/api` через Vite, тогда CORS не нужен:

```ts
// vite.config.ts
server: { proxy: { '/api': 'http://127.0.0.1:8080' } }
```

Ответы - JSON. Ошибка всегда `{"error": "..."}`. Пустые списки - `[]`. Время - RFC 3339.

## Вход

1. `GET /api/personas` - список тестовых сотрудников для экрана выбора.
2. `POST /api/auth/login {"user_id"}` -> `{token, user, expires_in}`. Токен живет 12 часов.
3. Дальше заголовок `Authorization: Bearer <token>`. На `401` - вернуть на экран входа.

Роль из `user.role`: `intern`, `mentor`, `lead`. От нее зависит, какие экраны показывать.

## Экраны и эндпоинты

| Экран | Запросы |
|---|---|
| Чат | `POST /api/chat`, затем карточки из `drafts` |
| Панель заявок | `GET /api/requests`, фильтр `?kind=access\|helpdesk\|equipment` |
| Заявка | `GET /api/requests/{id}` - с историей |
| Путь адаптации | `GET /api/onboarding`, отметить свой шаг: `POST /api/onboarding/steps/{step}/complete` |
| Мои доступы | `GET /api/access` |
| Наставник: стажеры | `GET /api/mentees`, путь стажера: `GET /api/mentees/{user}/onboarding` |
| Наставник: отметить шаг | `POST /api/mentees/{user}/steps/{step}/complete` |
| Наставник: согласования | `GET /api/approvals`, решение: `POST /api/approvals/{id}/approve` или `/reject` с `{"comment"}` |

## Чат

`POST /api/chat {"message", "thread_id"}`. Ответ синхронный: обычно 3-15 секунд, на бесплатной модели бывает дольше.
Показывай индикатор, остальной интерфейс не блокируй. `thread_id` хранится на клиенте, новый id - новый диалог.

В ответе:
- `reply` - текст помощника;
- `drafts` - все черновики пользователя (статус `draft`). Каждый - карточка с кнопками
  «Подтвердить» (`POST /api/requests/{id}/confirm`) и «Отменить» (`POST /api/requests/{id}/cancel`);
- `tools_used` - что делал агент, можно показать мелким текстом («проверил доступы, создал черновик»).

`502` - помощник недоступен. Поле `error` можно показать как есть, заявки и статусы при этом работают.

## Карточка заявки

- `title` - заголовок.
- `status` - см. таблицу ниже.
- `approver_name` - кто согласует.
- `resolution` - причина отказа или итог («Готово к выдаче: IT-склад, 3 этаж»).
- `policy.verdict == "needs_mentor"` - заявка не по роли. Показать `policy.reasons` и подсказку
  «Рекомендуем обсудить с наставником». Кнопка «Подтвердить» остается: после нее заявка уйдет наставнику.

После подтверждения статус меняется сам примерно через 15 секунд. Опрашивай `GET /api/requests` раз в 3-5 секунд,
пока есть заявки в нефинальном статусе.

| status | Подпись | Финальный |
|---|---|---|
| `draft` | Черновик | нет |
| `pending_mentor` | Ждет наставника | нет |
| `in_review` | На согласовании | нет |
| `new` | Зарегистрировано | нет |
| `in_progress` | В работе | нет |
| `waitlisted` | В листе ожидания | нет |
| `approved` | Одобрено | да |
| `ready` | Готово к выдаче | да |
| `rejected` | Отказ | да |
| `cancelled` | Отменено | да |

## Путь адаптации

`steps[]` сгруппировать по `week`. У шага `confirm`:

| confirm | Кто отмечает | Кнопка для стажера |
|---|---|---|
| `self` | стажер | «Готово» |
| `mentor` | наставник | нет, показать `hint` |
| `lead` | руководитель | нет, показать `hint` |
| `auto` | система, когда выдадут доступ к `auto.service` | нет |

`next` - следующий шаг, его стоит выделить. `open_requests` - незакрытые заявки для боковой панели.

## Коды ответа

| Код | Когда |
|---|---|
| 400 | неверный JSON или пустое сообщение |
| 401 | нет токена или он истек |
| 403 | шаг адаптации отмечает не тот, кто должен |
| 404 | нет такой заявки или она чужая (чужие заявки специально выглядят как несуществующие) |
| 409 | заявка уже не черновик; позиция закончилась на складе |
| 502 | помощник недоступен |

## Быстрая проверка из терминала

```bash
T=$(curl -s -X POST 127.0.0.1:8080/api/auth/login -d '{"user_id":"anna.intern"}' | jq -r .token)
curl -s 127.0.0.1:8080/api/onboarding -H "Authorization: Bearer $T" | jq '.next'
curl -s -X POST 127.0.0.1:8080/api/chat -H "Authorization: Bearer $T" \
  -d '{"message":"мне нужно поправить алерт в дашборде платежей"}' | jq
```
