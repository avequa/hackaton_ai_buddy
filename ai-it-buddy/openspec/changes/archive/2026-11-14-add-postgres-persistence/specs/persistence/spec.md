# Spec Delta

## Purpose
Состояние ядра переживает перезапуск, а недоступная база не останавливает помощника.

## ADDED Requirements

### Requirement: Сохранность между перезапусками
При заданном `DATABASE_URL` ядро SHALL восстанавливать при старте заявки, доступы, остатки склада, выдачи, шаги адаптации, инциденты, уведомления, события безопасности и темы для сводки. Нумерация заявок и уведомлений MUST продолжаться, а не начинаться заново.

#### Scenario: Перезапуск ядра
- **WHEN** стажер подтвердил стартовый набор и ядро перезапустили
- **THEN** заявки, выданные доступы и уведомления на месте, новая заявка получает следующий номер

#### Scenario: Первый запуск на пустой базе
- **WHEN** база пустая
- **THEN** ядро записывает начальное состояние из YAML (выданные доступы, склад) и работает с ним

### Requirement: Работа при недоступной базе
Если запись в базу не удалась, ядро SHALL продолжать отвечать из памяти и MUST повторять запись, пока база не вернется. `/readyz` MUST показывать `degraded`, число незаписанных изменений и текст ошибки, оставаясь 200: снимать ядро с трафика незачем.

#### Scenario: База пропала на минуту
- **WHEN** Postgres недоступен, а стажер подтверждает заявку
- **THEN** заявка подтверждена, `/readyz` показывает degraded и pending_changes > 0, после возврата базы изменения записаны

### Requirement: Поиск по базе знаний в Postgres
При подключенной базе поиск SHALL выполняться полнотекстово с русской морфологией. При ошибке базы поиск MUST выполняться в памяти, а событие - учитываться в метрике `buddy_kb_fallback_total`.

#### Scenario: Разные формы слова
- **WHEN** стажер пишет «подключиться к впн»
- **THEN** первым найден документ «Не подключается VPN»
