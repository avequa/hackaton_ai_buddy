# Proposal

## Why

Ядро хранило заявки, доступы и уведомления в памяти: перезапуск контейнера стирал все, что стажер сделал за день. Для демо это незаметно, для пилота в компании - неприемлемо. Поиск по базе знаний без морфологии путал «подключается» и «подключиться» и не понимал жаргон.

## What Changes

- Состояние ядра (заявки, доступы, склад, выдачи, шаги адаптации, инциденты, уведомления, события безопасности, темы для сводки) пишется в Postgres.
- Ядро продолжает отвечать из памяти: изменения раз в секунду уходят в базу одной транзакцией. База недоступна - изменения копятся и дописываются потом.
- При старте состояние восстанавливается из базы; пустая база заполняется начальными данными из YAML.
- База знаний синхронизируется из `data/kb` при старте, поиск - полнотекстовый с русской морфологией и словарем жаргона, с запасным поиском в памяти.
- `/readyz` показывает состояние хранилища, метрики записи для Prometheus.

## Capabilities

### New Capabilities
- `persistence`: сохранность состояния между перезапусками и работа при недоступной базе

### Modified Capabilities

## Impact

Новый пакет `core/internal/store` (pgx, встроенные миграции), фоновая запись в `cmd/core`, сервис `postgres` в compose, переменная `DATABASE_URL` (без нее ядро работает только в памяти, как раньше).
